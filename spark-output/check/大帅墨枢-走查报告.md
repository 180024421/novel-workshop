## Findings（按严重度排序）

### 🔴 Blocker

1. **[链路通畅性 1.4] 队列汇总点章跳转会丢未保存正文**
   - 出现位置：`src/pages/StudioPage.tsx:314-318`（`jumpQueueChapter` → `selectChapter` 直接 `setChapterId`）
   - 问题：QueuePanel 完成汇总里点「第N章」切章时，没有像 AppLayout 侧栏 `jumpChapter`（`AppLayout.tsx:380`）那样先派发 `moshu:hotkey save` flush 自动保存。当前章刚打的字（<700ms 自动保存窗口内）会被新章稿件加载覆盖。PRD 明示「任何丢字回归都是不可豁免的 P0」。
   - 修复建议：`jumpQueueChapter` 内先 `window.dispatchEvent(new CustomEvent("moshu:hotkey", { detail: { action: "save" } }))`（或 `await saveNow()`）再 `selectChapter`，与 AppLayout 路径对齐。

### 🟠 Major

2. **[链路通畅性 1.3] 运行态失败行的「重试」按钮不生效，还会把失败记录抹掉**
   - 出现位置：`src/components/workbench/QueuePanel.tsx:101` + `src/pages/studio/useStudioGenerate.ts`（`queueAction` / `queueGate`）
   - 问题：单次失败时 gate 自动返回 `skip`，循环已进入下一章；此时用户点失败行「重试」→ `transition(retry)` 把该章从 failures 移除并置 `running:true`，但驱动循环不会回头写这一章，且记录从面板与完成汇总中消失——章被静默漏掉。
   - 修复建议：非介入态（`!pausedForReview && !quotaBlocked`）隐藏/禁用「重试」，或将 retry 事件改为把章号重新入队（runQueue 支持 pending 列表）。

3. **[链路通畅性 1.2] 队列「暂停」= 无痕消失，无终点态、无恢复通道；介入态下暂停还会留下僵尸循环**
   - 出现位置：`src/pages/studio/useStudioGenerate.ts:765-780`（`queueAction` pause 分支）、`src/components/workbench/queueLogic.ts:127`（`pause` 转移）
   - 问题：pause 后 `running:false` 且 `pausedForReview:false` → `isQueueVisible()=false`、`queueProgressLabel()=null`，QueuePanel 与进度胶囊同帧消失，已写章数与进度瞬间不可见，用户无法确认"停住了"，也回不来（"暂停"承诺可恢复，实际只能重新起队列）。另外若此刻循环正停在 gate 等待人工介入，`abort()` 无法打断 `await gate`，旧 runQueue 永久挂起；下次 resume 的 `resolveGate` 可能唤醒旧循环与新队列互踩。
   - 修复建议：pause 走 `finished:true` 进部分汇总（文案改"停止并汇总"），或新增可见的 paused 态 + 恢复按钮；`queueAction("pause")` 前先 `resolveGate("stop")` 再 abort。

4. **[内容文案 6.4/承诺不符] 补料卡文案「生成完自动继续写正文，无需切页」未兑现**
   - 出现位置：`src/components/workbench/InlineRepairCard.tsx:77` + 文件头 EXIT 注释；实际行为见 `useStudioGenerate.ts doRepair`（补齐后不自动续生成）
   - 问题：PRD S2 验收明确要求「补齐后自动继续生成正文」；当前补完只转绿灯，用户需再点一次生成，而 UI 文案向用户做了相反承诺。
   - 修复建议：`doRepair` 成功回调里接续触发原生成动作（记录 pendingGenerate）；短期至少把文案改为「补好后点生成即可，无需切页」。

5. **[与 PRD 一致性] 侧栏队列态角标（stateOverrides）未接线，PRD S1 验收「侧栏与编辑器同步切换」缺口**
   - 出现位置：`src/components/workbench/ChapterSidebar.tsx`（`stateOverrides` prop 已备好）/ `src/pages/AppLayout.tsx:490+`（挂载点未传）
   - 问题：队列 generating/queued/failed 状态只在 StudioPage 的 `gen.queue` 里，AppLayout 拿不到，侧栏角标在挂机期间仍是静态——Flow C 承诺的跨栏同步未闭环（flow-web.json 已记为 deviation，走查确认仍在）。
   - 修复建议：把 queue 状态上提到 AppContext，或经既有事件桥（类似 `CHAPTERS_DIRTY_EVENT`）广播给 AppLayout 传入 `stateOverrides`。

6. **[内容文案 6.x 信息准确性] 队列启动条「预估 ¥X」用的是单章 chat 生成预估，未乘以章数**
   - 出现位置：`src/pages/StudioPage.tsx:350`（`estimatedCost={cny(gen.estimatedCostCny)}`）
   - 问题：写 4 章的队列显示约 1 章的费用，Flow D 的核心卖点恰是费用透明，此处会系统性低估挂机成本（约 /4）。
   - 修复建议：按 `target - start + 1` 倍单章预估展示，或文案改「单章预估 X」。

7. **[无障碍基础 9.3] 章目录行从 `<button>` 退化为 `div + onClick`，键盘不可达**
   - 出现位置：`src/components/workbench/ChapterSidebar.tsx`（`.wsb-item` div）
   - 问题：旧版 chapter-nav 是可 Tab/Enter 的 button，重构后失去焦点顺序与 Enter 触发；对每天 4 小时的键盘流写作者是真回归。
   - 修复建议：改回 `<button>`（样式已可覆盖），或 `role="button" tabIndex={0}` + `onKeyDown` Enter/Space。
